# GPT smoke report — 2026-08-17

## Purpose

This run answers two separate questions raised during advisor review:

1. Can GPT produce executable, structurally diverse hypotheses without silently
   falling back to a hand-written bank?
2. Does the complete short-budget smoke already identify the correct constraint?

The answer is **yes** to the first question and **no** to the second. The smoke
validates the control flow and audit trail, not scientific constraint quality.

## Changes validated before the live run

- Strict OpenAI Responses API Structured Outputs are compiled into the same
  trusted constraint IR used by the local backend.
- Semantically equivalent surface forms are canonicalized: scalar
  `coupling=independent` becomes scalar `joint`, and a multivariate affine
  upper/lower inequality becomes the supported joint linear half-space. A
  genuinely unsupported structure, such as a multivariate equality band, is
  still rejected.
- Simple scalar and linear hypotheses compete against joint MLP hypotheses with
  structural and parameter-count penalties.
- Heterogeneous constraints are represented as typed clauses composed with
  `any_violation`. For example, an equality band on feature A and an upper bound
  on feature B compiles to two heads; a trajectory is safe only when both clauses
  are satisfied.
- Falsifiers generate a candidate pool without Oracle access. A single global
  acquisition rule then selects only the configured number of whole trajectories
  across all active hypotheses.
- Semantic revisions are requested only on non-terminal rounds, so every action
  can affect a following numeric round.

All 17 unit tests passed before the final live run.

### Semantic behavior

GPT proposed six valid initial structures with no repair, augmentation, or
fallback:

- joint planar forbidden region, MLP;
- joint planar affine forbidden boundary;
- scalar horizontal equality band;
- scalar vertical lower bound;
- scalar speed upper bound;
- joint affine position-progress corridor.

After round 1 it retained and targeted the vertical lower-bound hypothesis,
retired the speed and progress-corridor alternatives, and requested a targeted
intervention. Consequently round 2 trained four active hypotheses rather than
the original six. This is a real outer-loop bank update, not a logged but unused
proposal.

There were exactly two GPT interactions: initial synthesis and the actionable
round-1 revision. No terminal revision call was made because no subsequent round
could use it.

### Oracle accounting

- warmup queries: 12;
- round-1 candidate pool: 12, globally selected queries: 3;
- round-2 candidate pool: 6, globally selected queries: 3;
- total Oracle queries: 18.

The round-1 selected queries came from only three of the six source hypotheses;
round 2 selected two queries from the retained vertical hypothesis and one from
the joint spatial hypothesis. Every selected trajectory stored every active
hypothesis's frozen pre-query prediction, allowing one Oracle answer to update
the evidence for the whole bank.

### Quality result and interpretation

The final smoke champion was the scalar vertical lower bound. Its held-out
ground-truth metrics were poor: IoU `0.0`, false-safe rate `1.0`, and held-out
expert-safe rate `0.5`. The short run therefore selected the wrong semantic
structure even though GPT followed the schema and the outer-loop update worked.

This failure is important: replacing Qwen with GPT removes the formatting and
fallback bottleneck, but does not make sparse, imbalanced trajectory evidence
sufficient for reliable model selection. Scientific evaluation should use a
larger query/training budget, multiple random seeds, and report performance versus
Oracle calls. The deterministic/frozen-bank ablations remain necessary.

Artifacts are under `outputs/gpt_smoke_final/`, especially `result.json`,
`semantic_interactions.json`, `hypothesis_bank.json`, `evidence_history.json`, and
`query_diagnostics.json`.

## Information assumption

The semantic-only run sends only task text and the public variable schema. The
integrated semantic revisions receive aggregate trajectory-level evidence; they
do not receive hidden obstacle geometry, state-level violation labels, or final
IoU. The experiment harness alone owns the whole-trajectory membership Oracle
and the isolated final evaluator. This remains a stronger setting than
demonstration-only learning and must be described as membership-query active
constraint learning.
